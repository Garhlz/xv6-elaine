# 实验通用指导

## 作业难度

每项作业都会标明难度：

- 简单（Easy）：少于一小时，通常是为后续练习做准备的热身题。
- 中等（Moderate）：1 至 2 小时。
- 困难（Hard）：超过 2 小时。这类练习通常不需要写很多代码，但很难写对。

这些时间只是我们预期的粗略估计。部分可选题没有参考解答，因此难度完全是估测。如果你花费的时间超过我们的预期，请在 Piazza 联系我们，或来答疑时间寻求帮助。

练习通常不需要写很多代码，从几十行到几百行不等，但概念上较复杂，细节往往非常重要。因此，在写代码之前，请完成实验要求的阅读，通读相关文件并查阅文档（RISC-V 手册等资料位于[参考页面](https://pdos.csail.mit.edu/6.828/2021/reference.html)）。只有充分理解任务和解决方案后才开始编码。开始编码后，以小步骤实现（题目通常会建议如何分解），每一步测试成功后再进行下一步。

警告：不要等到截止日期前一天晚上才开始实验。把实验分成多次、分布在几天中完成，会更加高效。操作系统内核 bug 的表现可能令人困惑，理解并修复它可能需要大量思考和仔细调试。

## 调试技巧

- 确保理解 C 和指针。Kernighan 与 Ritchie 的《The C Programming Language（第二版）》对 C 有简洁的介绍。这里有一些有用的[指针练习](https://pdos.csail.mit.edu/6.828/2019/lec/pointers.c)。除非你已经非常精通 C，否则不要跳过或草草浏览这些练习。如果没有真正理解 C 指针，实验将带来难以言喻的痛苦，你最终还是得通过艰难的方式学会它们。相信我们，你不会想知道“艰难的方式”是什么。

  有几个常见指针用法尤其值得记住：

  - 若 `int *p = (int*)100`，则 `(int)p + 1` 和 `(int)(p + 1)` 是不同的数：前者为 `101`，后者为 `104`。指针加整数时，如第二种情况，整数会隐式乘以指针所指对象的大小。
  - `p[i]` 按定义等同于 `*(p+i)`，表示 `p` 所指内存中的第 `i` 个对象，而不是该对象的地址。上述指针加法规则使对象大于一个字节时这一定义仍能工作。
  - `&p[i]` 与 `(p+i)` 相同，得到 `p` 所指内存中第 `i` 个对象的地址。

  大多数 C 程序很少需要在指针和整数间转换，但操作系统经常这样做。遇到涉及内存地址的加法时，要问自己这是整数加法还是指针加法，并确认被加的值是否按需要乘以对象大小。

- 如果练习已部分运行，通过提交代码保存进度。之后若破坏了某些功能，就可以回到检查点，再以更小的步骤推进。想了解 Git，可参阅 [Git 用户手册](http://www.kernel.org/pub/software/scm/git/docs/user-manual.html)或[面向计算机科学学习者的 Git 概述](http://eagain.net/articles/git-for-computer-scientists/)。
- 测试失败时，务必弄清代码为什么失败。加入打印语句，直到理解发生了什么。
- 打印语句可能产生大量需要搜索的输出。可以在 `script` 中运行 `make qemu`（在你的机器上运行 `man script` 查看说明），将控制台输出记录到文件，再搜索该文件。别忘了退出 `script`。
- 很多时候打印语句就足够，但有时单步执行汇编或检查栈上的变量也有帮助。要用 GDB 调试 xv6，在一个窗口运行 `make qemu-gdb`，另一个窗口运行 `gdb`（或 `riscv64-linux-gnu-gdb`），设置断点，再输入 `c`（continue）；xv6 将运行到断点处。参见[使用 GNU 调试器](https://pdos.csail.mit.edu/6.828/2019/lec/gdb_slides.pdf)中的提示。
- 如果想查看编译器为内核生成的汇编，或查找某个内核地址处的指令，可查看 Makefile 编译内核时生成的 `kernel.asm`。Makefile 也会为所有用户程序生成 `.asm` 文件。
- 内核发生 panic 时会打印错误消息，其中包含崩溃时程序计数器的值。可以搜索 `kernel.asm` 找出该地址所在函数，也可以运行 `addr2line -e kernel/kernel pc-value`（详情见 `man addr2line`）。要获取栈回溯，可用 GDB 重新启动：一个窗口运行 `make qemu-gdb`，另一个窗口运行 GDB（或 `riscv64-linux-gnu-gdb`），在 `panic` 处设置断点（`b panic`），然后输入 `c`。内核触发断点后输入 `bt` 查看回溯。
- 如果内核挂起（例如由于死锁）或不能继续执行（例如执行内核指令时发生缺页异常），可使用 GDB 查找挂起位置。一个终端运行 `make qemu-gdb`，另一个终端运行 GDB（`riscv64-linux-gnu-gdb`），连接后在 GDB 中输入 `c`。内核看似挂起时，在 **GDB 终端**按 `Ctrl-C` 暂停执行，再输入 `bt` 查看回溯。

  > 译注：原文将此处的终端称为“qemu-gdb 窗口”，容易产生歧义。`bt` 是 GDB 命令，应在 GDB 提示符下执行。
- `qemu` 有一个“监视器”，可用于查询模拟机器的状态。按 `Ctrl-a c` 进入，其中 `c` 代表 console。特别有用的监视器命令是打印页表的 `info mem`。可能需要使用 `cpu` 命令选择 `info mem` 查看哪个核心，也可以使用 `make CPUS=1 qemu` 启动单核 QEMU。

花时间学习上述工具非常值得。
